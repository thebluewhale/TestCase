# 제품 정합성 검수: 이미지 한 장을 받았을 때의 작업 절차

이 문서는 배경지식이 없는 사람이나 AI가 `product_qa_reference.zip`의 코드로 이미지 한 장을 처음부터 끝까지 검사할 수 있도록 쓴 절차서입니다. 설계 배경과 실험 결과는 `product_qa_handover.md`에 있고, 이 문서는 "무엇을 어떤 순서로 하고, 각 단계에서 무엇을 확인하는가"만 다룹니다.

**가장 먼저 알아야 할 것: 이 PoC에는 제품을 자동으로 찾는 기능이 없습니다.** 제품을 감싸는 박스 좌표는 사람이나 AI가 이미지를 직접 보고 정해서 넣어 줍니다. 이 단계를 건너뛰고 자동 분할을 시도하면 복잡한 배경에서 실패합니다. 4.2절과 4.3절이 이 문제를 다룹니다.

---

## 1. 최소한의 배경지식

### 1.1 무엇을 하는 작업인가

AI로 생성한 광고 이미지 속 휴대폰이 실제 제품과 같은 형상인지 검사합니다. 카메라 개수와 위치, 본체의 가로세로 비율, 모서리 둥글기, 플래시 위치, 카메라 아일랜드(카메라를 감싸는 돌출 판) 모양을 봅니다.

### 1.2 어떻게 검사하는가

1. 제품의 "정답 형상"을 mm 단위로 적어 둔 **기준 팩**이 있습니다. 본체 치수, 카메라 원들의 위치와 지름, 돌출 높이가 들어 있습니다.
2. 이미지에서 제품의 **테두리 직선**과 **카메라 원**을 검출합니다.
3. 기준 팩을 이미지에 겹쳤을 때 검출 결과와 가장 잘 맞는 **카메라 자세**(제품이 얼마나 돌아가고 기울었는지)를 계산합니다.
4. 그 자세를 기준으로 항목별 수치를 재고, 허용치와 비교합니다.

### 1.3 결과는 세 가지 중 하나

모든 항목은 **통과 / 이상 / 판단 불가** 중 하나입니다. 가려져서 안 보이거나 너무 작게 찍혀 정밀도가 부족하면 판단 불가입니다. 억지로 통과나 이상을 내지 않습니다.

### 1.4 좌표계

- 후면을 바라봤을 때 **후면의 좌상단이 원점**입니다. 카메라가 있는 쪽이 왼쪽 위입니다.
- x는 오른쪽으로 0 ~ W, y는 아래로 0 ~ H, 단위는 mm입니다.
- 후면 유리가 z = 0이고, 카메라처럼 튀어나온 것은 z가 음수입니다.

### 1.5 기준 팩이 있는 모델

| 모델 | 기준 팩 파일 | 상태 |
|---|---|---|
| Galaxy S26 Ultra | `ref_back.json` (기본값) | 오피셜 이미지로 제작, 보정 완료 |
| Galaxy S25 Ultra | `ref_back_S25U_provisional.json` | **임시**. 손에 든 사진 3장의 평균으로 제작. 돌출 높이는 S26 Ultra 값을 복사 |

다른 모델을 쓰려면 환경변수로 지정합니다: `REF_PACK=ref_back_S25U_provisional.json`. 지정하지 않으면 S26 Ultra입니다. **이미지의 모델과 기준 팩이 다르면 결과는 의미가 없습니다.**

두 모델의 차이: S25 Ultra는 카메라 아일랜드가 없고, 원의 지름이 더 크며, 작은 원 두 개가 약 0.9mm 왼쪽에 있습니다. S25 Ultra에는 아일랜드 검사(4.6절)를 적용하지 않습니다.

## 2. 준비

- Python 3.12, opencv 5.0.0, numpy 2.5.4, scipy 1.18.1, scikit-image 0.26.0. GPU는 필요 없습니다.
- zip을 풀고 `product_qa_reference/poc/` 폴더로 이동합니다. **모든 명령은 이 폴더에서 실행합니다.** 스크립트가 현재 폴더에서 파일을 읽고 씁니다.
- 이미지마다 짧은 이름(`NAME`)을 하나 정합니다. 중간 파일이 이 이름으로 만들어집니다.

## 3. 전체 흐름

```bash
# 1) 이미지에 좌표 격자를 그려서 본다
python grid_preview.py /path/IMAGE.png grid.jpg

# 2) 격자에서 읽은 박스(원본 픽셀)로 분할한다 → NAME_rgba.png, NAME_seg_preview.jpg
python segment.py /path/IMAGE.png NAME X0 Y0 X1 Y1

# 3) 정규화 → n_NAME_rgba.png, n_NAME_meta.json
python prep.py NAME

# 4) 테두리·원 검출과 자세 추정, 오버레이 생성 (약 30~40초)
FAST=1 python pipeline3.py overlay.jpg NAME

# 5) 항목별 판정 → res_NAME.json (장당 1~3분)
python checks.py NAME

# 6) 플래시, 카메라 아일랜드
python flash.py NAME
python island_crop.py NAME && python island_check.py NAME      # S26 Ultra만
```

1), 2), 4) 뒤에는 반드시 **생성된 이미지를 직접 열어서 확인**합니다. 수치만 보고 넘어가면 잘못된 분할이나 뒤집힌 정합을 놓칩니다.

## 4. 단계별 상세

### 4.1 이미지를 본다

다음을 먼저 확인하고 적어 둡니다.

| 확인할 것 | 이유 |
|---|---|
| 어느 모델인가 | 기준 팩 선택 |
| 후면이 보이는가 | 지금 코드는 후면만 검사 |
| 제품이 대략 세워져 있는가 | 거꾸로이거나 50도 이상 돌아가 있으면 원 매칭이 실패함 |
| 손이나 물체에 가려진 변이 있는가 | 그 변을 쓰는 항목은 판단 불가가 됨 (정상 동작) |
| 화면 밖으로 잘린 부분이 있는가 | 같음 |
| 제품이 몇 픽셀 높이로 찍혔는가 | 약 600px 미만이면 원 크기 항목은 판단 불가 (큰 원이 55px 미만) |

### 4.2 박스 좌표를 정한다

제품 전체를 감싸는 사각형의 왼쪽 위 `(X0, Y0)`와 오른쪽 아래 `(X1, Y1)`를 **원본 이미지의 픽셀 좌표**로 정합니다.

```bash
python grid_preview.py /path/IMAGE.png grid.jpg
```

`grid.jpg`는 이미지를 줄인 사본에 노란 격자를 그린 것이고, 격자의 숫자는 **원본 픽셀 좌표**입니다. 이 이미지를 열어서 제품의 상하좌우 끝이 어느 격자선 근처인지 읽습니다. 예시: `examples/01_grid_preview_Good_02.jpg`.

박스를 정하는 규칙:

- 보이는 제품 전체가 들어가야 합니다. 측면 프레임, 튀어나온 버튼까지 포함합니다.
- 제품 바깥으로 폭의 1~3% 정도 여유를 둡니다. 너무 넓게 잡지 않습니다.
- 박스가 제품을 자르면 안 됩니다. 애매하면 넓게 잡는 쪽이 안전합니다.
- 손에 든 사진은 손가락이 박스에 들어가도 됩니다. 다음 단계에서 걸러집니다.
- 제품이 화면 밖으로 잘린 쪽은 이미지 경계(0 또는 이미지 크기)를 그대로 씁니다.

**흔한 실수**: 화면에 표시된 이미지는 원본보다 줄어 있는 경우가 많습니다. 눈대중으로 읽은 좌표를 그대로 쓰면 박스가 엉뚱한 곳에 갑니다. 예를 들어 `Good_02_1.png`는 원본이 5504 × 3072인데 화면에는 2576px 폭으로 보입니다. 반드시 격자의 숫자를 읽습니다.

### 4.3 분할한다

```bash
python segment.py /path/IMAGE.png NAME X0 Y0 X1 Y1
```

출력은 `NAME_rgba.png`(원본에 제품 마스크를 알파 채널로 붙인 것)와 `NAME_seg_preview.jpg`(확인용)입니다.

#### 분할이 동작하는 원리

OpenCV의 GrabCut을 씁니다. 박스가 주는 정보는 두 가지입니다. **박스 바깥은 확실히 배경**이고, **박스 안은 아마도 제품**입니다. GrabCut은 박스 바깥의 색 분포로 "배경 색 모델"을, 박스 안의 색 분포로 "제품 색 모델"을 만든 뒤, 각 픽셀이 어느 쪽에 가까운지와 이웃 픽셀과의 경계 강도를 함께 고려해 제품과 배경을 나눕니다. 이 과정을 8회 반복합니다.

배경이 복잡해도 동작하는 이유는 박스가 배경의 색을 알려주기 때문입니다. 물결이나 숲처럼 복잡한 배경도 박스 밖에 충분히 보이면 배경으로 학습됩니다. 휴대폰은 색이 고른 큰 물체라 제품 쪽 모델도 안정적입니다.

스크립트가 하는 일을 순서대로 적으면 다음과 같습니다.

1. 긴 변이 1100px을 넘으면 1100px로 줄입니다 (속도와 안정성).
2. 박스로 GrabCut을 초기화하고 8회 반복합니다.
3. 제품으로 분류된 픽셀 중 **가장 큰 덩어리 하나만** 남깁니다.
4. 5×5 닫힘 연산으로 작은 구멍을 메웁니다.
5. 피부색 제거: YCrCb 색공간에서 Cr > 142이고 Cb < 124인 픽셀을 피부로 봅니다. 마스크의 2~40%가 피부색이면 그 부분을 제거하고 다시 가장 큰 덩어리만 남깁니다. 그 범위 밖이면 아무것도 하지 않습니다.
6. 원본 크기로 되돌리고 경계를 살짝 흐리게 한 뒤 저장합니다.

#### 진단 수치 읽는 법

스크립트는 한 줄을 출력합니다.

```
Good_02_1: mask/box area 0.80 | mask/convex-hull 0.972 | touches box border: none | skin fraction 0.000
```

| 수치 | 뜻 | 정상 범위 |
|---|---|---|
| mask/box area | 박스 면적 중 마스크의 비율 | 세워진 폰은 0.75~0.95. 기울어진 폰은 0.45~0.7 |
| mask/convex-hull | 마스크가 볼록한 정도 | 0.95 이상. 낮으면 마스크가 크게 파였거나 삐져나온 것 |
| touches box border | 마스크가 박스 경계에 닿은 변 | none이 정상. 닿았다면 박스가 제품을 잘랐거나, 그 방향으로 마스크가 샌 것 |
| skin fraction | 피부색 비율 | 손이 없으면 0 근처 |

`touches box border`가 뜨는 정상적인 경우도 있습니다. `Hand_08`은 손이 하단을 감싸고 있어 마스크가 손 쪽으로 이어져 `bottom`이 뜹니다. 이때는 미리보기에서 나머지 변이 제대로 잡혔는지만 확인하고 진행합니다.

#### 미리보기에서 확인할 것

`NAME_seg_preview.jpg`를 엽니다. 배경은 어둡게, 마스크 경계는 녹색 선으로, 박스는 노란 사각형으로 그려져 있습니다. 예시: `examples/02_seg_preview_Good_02.jpg`, `04_seg_preview_Hand_08.jpg`, `06_seg_preview_Good_01.jpg`.

**반드시 만족해야 하는 것**

- 제품의 긴 변 두 개(좌·우) 중 적어도 대부분이 마스크 경계와 일치한다.
- 상변이나 하변 중 적어도 하나가 마스크 경계와 일치한다.
- 제품이 아닌 큰 영역(탁자, 소매, 배경 물체)이 마스크에 붙어 있지 않다.

**완벽하지 않아도 되는 것**

- 가려진 변이 물체 모양대로 울퉁불퉁하다 (`Good_02`의 하단은 바위 모양을 따라감).
- 마스크 일부가 파여 있다 (어두운 카메라 부분이 잘려 나간 경우 등).
- 손가락 끝이 조금 붙어 있다.

완벽하지 않아도 되는 이유는 다음 단계들이 이를 견디도록 만들어져 있기 때문입니다.

- 테두리 직선은 마스크 윤곽 중 **볼록 껍질 위에 있는 점만** 써서 찾습니다. 파인 부분은 자동으로 무시됩니다.
- 찾은 직선이 충분히 곧지 않거나 너무 짧으면 버립니다. 그 변을 쓰는 항목이 판단 불가가 될 뿐입니다.
- 카메라 원은 마스크가 아니라 **마스크의 볼록 껍질 안쪽 전체**에서 찾습니다. 카메라 부분이 마스크에서 빠져도 원은 검출됩니다.

#### 분할이 잘못됐을 때

| 증상 | 조치 |
|---|---|
| 마스크가 배경으로 크게 번짐 | 박스를 제품에 더 바짝 붙여 다시 실행 |
| 제품의 일부가 통째로 빠짐 | 박스가 제품을 자르지 않았는지 확인. 그래도 빠지면 `--fg` 사용 |
| 제품과 비슷한 색의 배경이 붙음 | `--fg` 사용 |
| 손이 통째로 붙어 있음 | skin fraction이 0.4를 넘어 제거가 생략된 것. 박스를 줄여 손이 덜 들어가게 함 |
| 본체가 피부색 계열이라 본체가 깎임 | `--no-deskin` 추가 |

`--fg`는 "여기는 확실히 제품"인 사각형을 하나 더 주는 옵션입니다. 후면 한가운데의 넓은 영역을 주면 됩니다.

```bash
python segment.py /path/IMAGE.png NAME 2130 130 3340 2900 --fg 2400 1100 3100 2300
```

`--fg`는 동작하는 것만 확인했고, 지금까지의 시험 이미지에서는 필요하지 않았습니다.

여러 번 고쳐도 분할이 안 되면 그 이미지는 "분할 실패로 판단 불가"로 보고합니다. 서비스에서는 이 단계를 프롬프트 기반 분할 모델로 바꿀 예정입니다.

### 4.4 정규화

```bash
python prep.py NAME
```

마스크 경계 상자에 12% 여백을 두고 자른 뒤, 긴 쪽이 1400px이 되도록 크기를 맞춥니다. 이후 단계의 픽셀 단위 설정이 모두 이 크기를 기준으로 합니다. 원본 이미지의 중심 좌표(카메라 주점으로 가정)는 변환해서 `n_NAME_meta.json`에 저장합니다. 확인할 것은 없습니다.

### 4.5 테두리·원 검출과 자세 추정

```bash
FAST=1 python pipeline3.py overlay.jpg NAME
# S25 Ultra라면
REF_PACK=ref_back_S25U_provisional.json FAST=1 python pipeline3.py overlay.jpg NAME
```

출력 예:

```
== Good_02_1 (x0.55)  tilt=30°  f/W=1.5  valid=lrt
   lenses measured=[0, 1, 2, 3, 4] unmeasured={} extra=0  d_big=[15.8 15.6 15.6] d_small=[8.6 8.6]
   FitA rms(σ)={'lens': 0.3, 'ratio': 0.3, 'left': 0.1, 'right': 0.2, 'top': 0.7}  lens pos err mm=[0.17 0.03 0.04 0.06 0.05]
```

| 출력 | 뜻 | 정상 |
|---|---|---|
| `valid=lrt` | 유효하다고 인정된 변. l 좌, r 우, t 상, b 하 | 좌·우와 상·하 중 하나 이상 |
| `lenses measured=[0,1,2,3,4]` | 기준 팩의 원 중 측정된 것. 0~2가 큰 원(위에서 아래), 3~4가 작은 원 | 5개 모두, 또는 `unmeasured`에 `present`로 표시 |
| `unmeasured={2: 'ABSENT'}` | 측정되지 않은 원. `ABSENT`는 그 자리에 원이 없다는 뜻 | 비어 있음 |
| `extra` | 기준 팩에 없는 원이 후면 안쪽에서 검출된 수 | 0 |
| `FitA rms(σ)` | 관측과 기준 팩의 불일치. 예상 잡음 단위 | 각 값이 3 이하 |
| `lens pos err mm` | 원별 위치 오차 | 1.5mm 이하 |
| `tilt`, `f/W` | 기울기, 초점거리 ÷ 이미지 폭 | 정면에 가까운 구도에서는 믿을 수 없는 값이 나옴 (정상) |

**오버레이를 반드시 엽니다.** 예시: `examples/03_steps_Good_02.jpg`의 오른쪽.

| 색 | 뜻 |
|---|---|
| 파란 선 | 검출되어 인정된 테두리 직선 |
| 빨간 선 | 검출됐지만 버려진 직선 |
| 밝은 녹색 사각형 | 기준 팩의 후면 사각형을 추정한 자세로 그린 것 |
| 어두운 녹색 사각형 | 두께만큼 뒤에 있는 전면 사각형 |
| 노란 원 | 기준 팩의 원이 있어야 할 자리 |
| 빨간 점 | 실제로 측정된 원의 중심 |
| 자홍색 원 | 기준 팩에 없는 추가 검출 |

확인할 것:

- 녹색 사각형이 제품의 실제 테두리와 겹치는가. 측면이 보이는 쪽은 어두운 녹색이 바깥 실루엣에 겹칩니다.
- 노란 원이 실제 카메라 위에 있는가.
- 사각형이 뒤집히거나 옆으로 밀려 있지 않은가.

녹색 사각형과 노란 원은 **검출 결과가 아니라 기준 팩을 그려 넣은 것**입니다. 이 점은 5절에서 자세히 설명합니다.

### 4.6 항목별 판정

```bash
python checks.py NAME          # → res_NAME.json
python flash.py NAME           # → flash_NAME.json, flash_NAME.jpg
python island_crop.py NAME && python island_check.py NAME
```

S25 Ultra 이미지라면 세 명령 모두 앞에 `REF_PACK=ref_back_S25U_provisional.json`을 붙이고, 아일랜드 검사는 생략합니다.

`res_NAME.json`의 항목과 현재 코드의 기준:

| 항목 | JSON 키 | 이상으로 보는 기준 |
|---|---|---|
| 원 개수 | `count` | 측정 + 존재 확인이 5가 아니거나 추가 검출이 있음 |
| 종횡비 | `aspect` | 정면: 3% 초과. 기울어진 구도: 5% 초과이면서 σ의 3배 초과 |
| 원 위치 | `position` | 가장 어긋난 원이 폰 높이의 1.5% 초과 |
| 원형도 | `round` | 8% 초과 |
| 원 크기 | `size` | 15% 초과. 큰 원이 55px 미만이면 판단 불가 |
| 모서리 R | `cornerR` | 기준에서 25% 초과. 정면 구도만 |

각 항목의 `verdict`는 `OK`, `NG`, `NA`(판단 불가), `OK*`(기울어진 구도에서 5% 한계 안)입니다.

`aspect.method`가 `direct`면 정면 구도로 판별되어 테두리를 직접 잰 것이고, `fitC`면 기울어진 구도라 피팅으로 구한 것입니다. 기울어진 구도에서는 5% 미만의 종횡비 오류를 원리적으로 가릴 수 없습니다.

`handover` 문서 6.11절에 "합의된 수정" 목록이 있습니다(기울어진 구도 σ의 4배, 원형도 픽셀 게이트 등). 코드에는 반영되어 있지 않으므로 결과를 해석할 때 함께 적용합니다.

플래시는 `flash_NAME.json`의 `found`, 위치 `x`, `y`를 기준값과 비교합니다. S26 Ultra의 기준은 (32.93, 23.88)이고 허용치는 2mm, 지름은 판정에 쓰지 않습니다. S25 Ultra의 임시 기준은 (31.69, 23.42)입니다.

아일랜드는 `island_check.py`가 `OK` 또는 `NG`를 출력합니다. 윤곽 검출 비율 90% 미만이 NG입니다. S26 Ultra 전용입니다.

### 4.7 결과 보고

- 항목별로 통과 / 이상 / 판단 불가와 측정값을 적습니다.
- 판단 불가인 항목은 이유를 적습니다 (가려짐, 해상도 부족, 구도).
- 오버레이 이미지를 함께 붙입니다.
- 코드에 없는 항목(로고, 측면 버튼, 색상, 덧그려진 형상)은 검사하지 않았다고 적습니다.

## 5. 보이지 않는 경계를 어떻게 그리는가

`GalaxyS25U_Hand_08.png`는 손이 휴대폰 하단을 감싸고 있어 하단 테두리가 보이지 않습니다. 그런데 오버레이에는 하단까지 사각형이 그려집니다. 이것은 **보이지 않는 경계를 검출한 것이 아니라, 알고 있는 치수와 추정한 자세로 계산해서 그린 것**입니다.

`examples/05_outline_explained_Hand_08.jpg`에 구분해서 그려 두었습니다. 흰 선은 분할 마스크의 윤곽, 파란 선은 검출되어 인정된 직선, 녹색 변은 검출된 직선이 뒷받침하는 기준 팩의 변, **자홍색 변은 검출된 직선 없이 계산으로만 그린 변**입니다.

### 5.1 원리

알고 있는 것과 모르는 것을 나누면 이렇습니다.

| 구분 | 내용 |
|---|---|
| 미리 알고 있는 것 (기준 팩) | 본체 가로 77.6mm, 세로 162.8mm, 두께 8.2mm, 카메라 원 5개의 mm 좌표와 높이 |
| 이미지에서 관측한 것 | 좌변, 우변, 상변의 직선 3개, 원 5개의 중심과 찌그러진 정도(장단축비) |
| 구해야 하는 것 | 카메라 자세 7개 값 (회전 3, 위치 3, 초점거리 1) |

관측에서 나오는 식의 수는 원 중심 5개 × 2, 장단축비 5개, 직선 3개 × 2로 모두 21개입니다. 미지수 7개를 구하기에 충분합니다. 최소자승으로 "기준 팩을 이 자세로 놓으면 관측과 가장 잘 맞는다"는 자세를 찾습니다.

자세가 정해지면 기준 팩의 **어떤 점이든** 이미지의 어느 픽셀에 오는지 계산할 수 있습니다. 후면의 네 모서리 (0, 0), (W, 0), (W, H), (0, H)를 투영해 이으면 사각형이 됩니다. 하단 변은 "이 제품의 세로가 스펙대로 162.8mm라면 여기에 있어야 한다"는 위치입니다.

비유하자면, 크기를 아는 책의 위쪽 절반만 보여도 책이 놓인 각도를 알면 아래쪽 끝이 어디인지 알 수 있는 것과 같습니다.

### 5.2 Hand_08에서 실제로 일어난 일

1. 박스 `345 168 782 1048`로 분할. 마스크가 하단에서 손 쪽으로 이어져 `touches box border: ['bottom']`이 나옴.
2. 마스크 윤곽에서 직선 4개를 찾음. 좌·우·상변은 인정, **하단 직선 후보는 기준 미달로 버려짐** (`valid=lrt`).
   - 인정 기준: 직선에서 벗어난 정도가 폰 높이의 0.3% 미만, 길이가 폰 높이의 35%(좌·우) 또는 12%(상·하) 이상
3. 원 5개를 모두 검출하고 기준 팩과 짝지음.
4. 변 3개와 원 5개로 자세를 계산. 원 위치 오차는 0.15~0.39mm.
5. 그 자세로 기준 팩의 사각형과 원을 그림.

`Good_02_1.png`(바위에 하단이 가린 이미지)도 같은 방식입니다. `valid=lrt`이고 녹색 사각형의 하단이 바위 뒤로 이어집니다.

### 5.3 검사에서의 의미와 주의점

- **계산해서 그린 변은 증거가 아닙니다.** 하단이 실제로 거기 있는지는 확인된 것이 아닙니다. 따라서 그 변이 필요한 항목은 판단 불가입니다.
  - Hand_08에서 판단 불가가 되는 것: 세로 길이, 정면 방식의 종횡비(4변 필요), 하단 모서리 R
  - 판단할 수 있는 것: 원 개수와 위치, 폭 방향 정합, 플래시
- **사각형이 테두리와 잘 겹쳐 보이는 것은 당연한 결과가 아닙니다.** 보이는 변과 원이 기준 팩과 일관될 때만 그렇게 됩니다. 원 배치가 틀렸거나 폭이 다르면 보이는 변에서 사각형이 어긋나고 `FitA rms`가 커집니다.
- **정면에 가까운 구도에서는 기울기 값을 믿을 수 없습니다.** Hand_08의 `tilt`는 실행에 따라 5~14도로 달라졌습니다. 사각형이 그려지는 위치에는 거의 영향이 없습니다.
- **기준 팩이 틀리면 그림도 틀립니다.** S25 Ultra 이미지에 S26 Ultra 기준 팩을 쓰면 작은 원이 약 1mm 어긋나게 그려집니다.
- **시험된 범위**: 변 3개 + 원 5개 조합까지 확인했습니다. 변이 2개 이하이거나 원이 3개 이하인 경우는 시험하지 않았습니다. 계산으로 그린 변이 실제 위치와 얼마나 가까운지도 따로 측정하지 않았습니다.

## 7. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 분할 결과가 제품이 아님 | 박스를 주지 않았거나 좌표가 표시 크기 기준 | 4.2절대로 격자에서 원본 좌표를 읽음 |
| `lenses measured`가 비어 있거나 1~2개 | 분할이 카메라 영역과 본체를 크게 놓침, 또는 다른 모델 | 미리보기 확인, 기준 팩 확인 |
| `valid`에 좌·우 중 하나가 없음 | 그 변이 가려졌거나 마스크가 샘 | 미리보기에서 그 변 확인. 실제로 가려졌다면 정상 |
| 녹색 사각형이 뒤집히거나 크게 어긋남 | 제품이 거꾸로이거나 50도 이상 회전, 또는 기준 팩 불일치 | 이미지를 돌려서 제품을 세운 뒤 다시 실행 |
| `FitA rms`의 변 값이 10 이상 | 직선이 제품 테두리가 아닌 것(손가락, 물체)을 잡음 | 분할을 고침 |
| 모든 원의 위치 오차가 비슷하게 1mm 안팎 | 기준 팩이 다른 모델 | `REF_PACK` 확인 |
| `checks.py`가 몇 분씩 걸림 | 종횡비 피팅이 느림 | 정상. 급하면 `FAST=1 python pipeline3.py`로 자세만 확인 |
| 어두운 본체의 구석이 원으로 검출됨 (`extra=1`) | 알려진 가짜 검출 | 오버레이에서 자홍색 원 위치 확인 후 무시 |

## 8. 이 절차의 한계

- 박스는 사람이 정합니다. 자동 감지는 없습니다.
- 기준 팩이 있는 모델만 검사할 수 있습니다. S25 Ultra 팩은 임시입니다.
- 후면만 검사합니다.
- 제품이 거꾸로이거나 크게 돌아간 구도는 지원하지 않습니다.
- 기준값은 소수의 이미지를 보며 정한 것이고, 라벨을 가린 평가는 하지 않았습니다.
- 그 밖의 한계와 알려진 문제는 `product_qa_handover.md` 10장에 있습니다.
