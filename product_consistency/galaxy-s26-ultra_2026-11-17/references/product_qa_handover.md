# 제품 정합성 검수 서비스: 조사와 PoC 정리

AI로 생성한 광고 이미지 속 자사 제품이 실제 제품과 같은 형상인지 검수하는 서비스를 만들기 위한 사전 조사와 PoC 결과를 정리한 문서입니다. 이 문서와 첨부 코드(`product_qa_reference.zip`)를 기준으로 다른 환경에서 서비스 코드를 작성하는 것을 전제로 썼습니다.

- 대상 제품: Galaxy S26 Ultra (바형 휴대폰) 후면
- 기준 자료: 오피셜 마케팅 이미지(전면, 후면, 좌·우 측면, 사선 30도)와 실측 치수 163.6 × 78.1 × 7.9 mm
- 시험 이미지: 오피셜 10장, 생성 이미지 14장
- 3D 애셋은 없다고 가정

읽는 순서: 2장(결론) → 4장(원리) → 6장(파이프라인) → 10장(한계) → 12장(첨부 코드).

이미지 한 장을 받아 실제로 검사하는 절차(박스 정하기, 분할, 확인 방법)는 별도 문서 `product_qa_runbook.md`에 있습니다. 코드를 실행하려면 그 문서를 먼저 봅니다.

---

## 1. 목표와 범위

- **목표**: 생성 이미지에서 제품 영역을 찾고, 크기 비율과 랜드마크가 스펙과 맞는지 항목별로 판정한다.
- **판정 수준**: 100% 정확도가 아니라 "사람이 봐도 이상한 수준"만 지적한다.
- **3값 판정**: 모든 항목은 통과 / 이상 / 판단 불가 중 하나를 낸다. 보이지 않거나 측정 정밀도가 부족하면 판단 불가다.
- **PoC 범위**: 바형 폰 1개 모델의 후면, 정지 이미지. 영상, 전면, 다른 제품군, 자동 영역 감지, UI는 범위 밖이다.

## 2. 결론 요약

1. **유사 상용 서비스는 없다.** 가장 가까운 것도 패션·식품만 지원한다. 자체 구축이 맞다.
2. **3D 애셋 없이 가능하다.** 오피셜 이미지와 실측 치수로 만든 "면 템플릿 + 박스 프록시"로 자세를 역산할 수 있었다. 오피셜 사선 30도 이미지에서 기울기 -30.2도, +30.0도가 복원됐다.
3. **기하 측정과 형상 판단은 서로 다른 오류를 잡는다.** 종횡비 16% 변형(Test_15)은 기하 측정으로만, 카메라 아일랜드 모양 오류(Test_06)는 형상 검사로만 잡혔다. 두 층이 모두 필요하다.
4. **항목마다 기준 프레임을 따로 둔다.** 종횡비만 절대 기울기가 필요하고, 나머지는 외곽 기준으로 재면 된다. 이렇게 해야 원인 하나에 경고 하나가 나온다.
5. **사선 구도의 종횡비에는 수학적 한계가 있다.** 균일하게 늘어난 평면은 "덜 기울어진 정상 제품"과 구분되지 않는다. 사선 구도에서 5% 미만은 판단 불가로 둔다.
6. **현재 성적**: 정상 8장은 종합 판정 모두 통과, 이상 5장은 모두 어느 항목에서 검출. 단, 이 이미지들을 보면서 기준을 조정했으므로 검증된 성능이 아니다.
7. **서비스에서 교체할 부분**: 분할(손으로 준 박스 + GrabCut), 초점거리 추정, 속도(사선 종횡비 피팅이 CPU에서 장당 1~2분).

## 4. 핵심 원리

### 4.1 3D 없이 가는 방법: 면 템플릿 + 박스 프록시

바형 폰은 직육면체에 가깝고 검수 대상 랜드마크 대부분이 평평한 후면 위에 있다. 그래서 다음 네 가지로 3D 모델을 대신한다.

1. **면 템플릿**: 오피셜 후면 이미지를 실측 치수로 mm 스케일에 맞추고 랜드마크를 mm 좌표로 기록
2. **높이 정보**: 랜드마크가 면에서 튀어나온 높이(렌즈, 아일랜드)
3. **박스 프록시**: 가로 × 세로 × 두께 직육면체. 측면이 보일 때 실루엣을 설명
4. **검증용 이미지**: 사선 30도 이미지는 템플릿 제작에 쓰지 않고 프록시 검증과 보정에 사용

오피셜 정면 이미지는 정사영에 가깝다는 가정이 필요하고, 실제로 종횡비가 스펙과 0.1% 차이로 일치했다.

### 4.2 식별 가능성: 균일한 늘림은 기울임과 같다

**원근이 약할 때, 평면을 한 방향으로 늘린 이미지는 같은 평면을 다른 각도에서 본 이미지와 수학적으로 같다.** 평면의 임의 선형 변형(자유도 4)은 스케일 1 + 3D 회전 3으로 정확히 표현되기 때문이다.

따라서 다음이 성립한다.

- "제품이 스펙대로"라고 가정하고 구한 기울기로 종횡비를 재면 순환 논리가 되어 항상 스펙과 비슷하게 나온다.
- 템플릿과 이미지 사이에 호모그래피를 자유롭게 맞추면 늘어난 제품도 오차 없이 맞는다(호모그래피 자유도 8, 실제 카메라 7).
- 종횡비를 판단하려면 **평면 밖의 단서**가 필요하다: 측면 두께, 렌즈 돌출 높이, 강한 원근, 또는 정면 구도.

실험으로 확인한 사실:

| 실험 | 결과 |
|---|---|
| 정상 이미지를 가로 5% 늘림 | 피팅이 약 19도 기울어진 것으로 해석, 잔차는 폰 높이의 0.2% |
| 가로 10% 늘림 | 역시 기울기로 흡수되어 잔차가 같은 수준에 머묾 |
| 36도 구도에서 4% 늘림 vs 3.5도 덜 기울어짐 | 측면 두께에서 0.6mm, 렌즈 시차에서 0.3mm 차이. 1mm가 3px인 이미지에서 1~2px |
| 같은 구도에서 16% 늘림 | 2.7mm와 1.5mm, 즉 8px와 5px 차이. 검출 가능 |

뷰 유형별 판단 가능성(product-metrology 스킬의 판별표와 동일한 내용):

| 뷰 | 판단 가능한 것 |
|---|---|
| 정면 | 종횡비를 직접 측정. 렌즈 원형도로 배제 못 하는 기울기(약 14도) 때문에 3% 안팎이 한계 |
| 한 축 회전 | 초점거리와 폭이 구분되지 않음. 측면 두께, 원형 랜드마크, 초점거리 중 하나가 있어야 풀림 |
| 두 축 회전 + 강한 원근 | 소실점 두 개로 초점거리와 종횡비를 함께 풀 수 있음 (이번 시험 이미지는 원근이 약해 미사용) |

### 4.3 항목별 기준 프레임 분리

| 검사 항목 | 기준을 무엇으로 잡나 | 전제 |
|---|---|---|
| 종횡비 | 정면이면 직접 측정. 사선이면 평면 밖 단서로 기울기를 구함 | 두께가 맞게 그려졌다 |
| 랜드마크 위치 | 외곽 기준, 폭·높이로 나눈 비율 (u, v) | 없음 |
| 원형도, 크기, 모서리 R | 외곽 기준 | 없음 |
| 개수 | 불필요 | 없음 |

오프셋을 mm가 아니라 비율로 정하는 이유: 종횡비가 틀린 이미지에서 mm 오프셋은 모든 랜드마크가 함께 어긋나 경고가 줄줄이 뜬다. 비율로 정하면 "종횡비 이상" 하나만 나온다.

### 4.4 사선 구도에서 두께와 종횡비의 얽힘

두께를 믿고 기울기를 구하면 두께를 검사할 수 없다. 렌즈로 기울기를 구해 두께를 검사하면 측면 띠가 7~14px일 때 오차가 10~20%다. 한 장에서 둘을 모두 정밀하게 검사할 수는 없다.

## 5. 기준 팩 (모델별 스펙)

기하 스펙은 색상별이 아니라 **모델별로 하나**면 된다. 보라색 이미지로 만든 기준 팩을 검정·흰색에 그대로 적용해 수치가 일치했다.

### 5.1 좌표계

- 원점: 후면을 바라봤을 때 후면의 좌상단
- x: 오른쪽으로 0 ~ W (78.1mm), y: 아래로 0 ~ H (163.6mm)
- z: 몸체 안쪽(전면 방향)이 양수. 후면 유리가 z = 0, 전면이 z = +7.9
- 후면에서 튀어나온 것은 z가 음수 (렌즈 윗면 z = -4.4)

### 5.2 Galaxy S26 Ultra 후면 값

| 항목 | 값 | 출처 |
|---|---|---|
| W × H × T | 78.1 × 163.6 × 7.9 mm | 공개 스펙 |
| 큰 원 3개 중심 (x, y) | (15.16, 15.18), (15.05, 33.28), (15.03, 51.46) | 오피셜 후면에서 측정 |
| 작은 원 2개 중심 | (32.90, 14.92), (32.90, 33.11) | 같음. 위쪽은 AF 센서로 보임 |
| 큰 원 지름 | 15.4 mm | 파이프라인 검출기로 잰 값 |
| 작은 원 지름 | 8.4 mm | 같음 |
| 큰 원 높이 | 4.4 mm | 측면 이미지 + 사선 30도 피팅(3.97, 4.93) |
| 작은 원 높이 | 1.7 mm | 사선 30도 피팅(1.55, 1.80) |
| 플래시 중심, 지름 | (32.93, 23.88), 4.02 mm, 높이 0 | 오피셜 후면에서 측정 |
| 아일랜드 윤곽 | 알약 모양: 중심축 x = 14.9, 반지름 10.1, 직선 구간 y = 14.9 ~ 51.2 | 오피셜 후면에서 추출. 범위 x 4.8~25.0, y 4.8~61.3 |
| 아일랜드 높이 | 2.6 mm | 측면 이미지에서 추정 |
| 모서리 R | 약 7.4 mm (모서리별 6.7~8.0) | 대각선 간격 방식으로 측정 |
| 둥근 프레임 보정 반지름 ρ | 2.2 mm | 사선 30도 이미지로 보정 |
| 후면 유리·프레임 경계 오프셋 δ | 0.5 mm | 사선 30도 이미지로 보정 |

주의: `ref_back.json`의 `d_mm`(16.3~16.5, 9.3)은 초기 임계값 방식으로 잰 값이고, 파이프라인은 자체 검출기로 잰 15.4, 8.4를 상수로 쓴다. 지름은 "어느 경계를 잡느냐"에 따라 달라지므로, 스펙을 만들 때와 검사할 때 **같은 검출기**를 써야 한다.

### 5.3 기준 팩을 만드는 절차

1. 오피셜 후면 이미지(투명 배경)의 외곽 4변을 추출해 종횡비가 스펙과 일치하는지 확인 (S26U: +0.11%)
2. 높이 기준으로 px/mm를 정하고 랜드마크를 mm 좌표로 기록
3. 측면 이미지에서 돌출 높이를 대략 측정
4. 사선 30도 이미지에 템플릿을 맞춰 높이, ρ, δ를 보정하고 기울기가 30도로 복원되는지 확인

## 6. 파이프라인 상세

첨부 코드 `poc/pipeline3.py`(자세 추정과 측정)와 `poc/checks.py`(항목별 판정)의 동작을 그대로 적었다. 수치는 모두 코드에 있는 값이다.

### 6.0 카메라 모델

- 핀홀, 렌즈 왜곡 없음, 정사각 픽셀
- 주점은 **원본 이미지의 중심**으로 가정 (크롭된 이미지에서는 깨질 수 있음)
- 투영: `X_cam = R·X + t`, `u = f·X_cam.xy / X_cam.z + pp`
- 자세 파라미터 7개: 회전 벡터 3, 이동 3, log f

### 6.1 제품 영역 분할 (임시 구현)

**자동 감지가 아니다.** 사람이나 AI가 이미지를 보고 제품을 감싸는 박스를 원본 픽셀 좌표로 정해서 넣는다. 박스 없이 자동 분할을 시도하면 복잡한 배경에서 실패한다. **서비스에서 교체할 부분**이다.

- `grid_preview.py`: 원본 픽셀 좌표가 적힌 격자 미리보기를 만들어 박스를 읽을 수 있게 함
- `segment.py IMAGE NAME X0 Y0 X1 Y1`: 박스로 GrabCut 실행
  - 긴 변 1100px 이하로 줄여 `cv2.grabCut` (사각형 초기화, 8회 반복). 박스 바깥은 확실한 배경, 안쪽은 제품 후보
  - 가장 큰 연결 성분만 남기고 5×5 닫힘 연산, 원본 크기로 되돌린 뒤 블러
  - 손에 든 이미지: YCrCb에서 Cr > 142, Cb < 124인 피부색 픽셀을 마스크에서 제거 (피부 비율이 2~40%일 때만 적용)
  - `--fg X0 Y0 X1 Y1`: 확실히 제품인 사각형을 추가로 지정 (마스크 초기화 방식). 동작만 확인했고 시험 이미지에서는 필요하지 않았음
  - 진단 출력: 마스크/박스 면적비, 마스크/볼록 껍질 면적비, 박스 경계 접촉 여부, 피부색 비율
- 결과물: `NAME_rgba.png` (BGR + 알파 마스크), `NAME_seg_preview.jpg` (확인용)

마스크는 완벽하지 않아도 된다. 뒤 단계가 파인 부분과 가려진 변을 견디도록 되어 있다(6.3, 6.4절). 박스 규칙, 진단 수치의 정상 범위, 실패 시 조치는 `product_qa_runbook.md` 4.2~4.3절에 있다.

### 6.2 정규화

- 마스크 경계 상자에 12% 여백을 두고 자른 뒤, 긴 쪽이 1400px이 되도록 확대·축소
- 주점 좌표를 같은 변환으로 옮겨 저장 (`pp`), 배율 `k`와 원본 폭 × k (`W`)도 저장
- 이후 모든 픽셀 단위 파라미터는 이 1400px 기준이다

저해상도 이미지를 확대해도 정보가 늘지는 않지만, 고정 스텝 알고리즘이 일정하게 동작한다.

### 6.3 외곽(테두리) 검출

회전된 구도, 손 가림, 마스크 결손에 견디도록 만든 방식이다.

1. 마스크 윤곽선의 모든 점 중 **볼록 껍질(convex hull) 위에 있는 점만** 사용 (껍질과의 거리 2.5px 미만)
   - 마스크가 파인 곳(어두운 카메라 영역이 잘려 나간 경우)은 껍질 위에 없으므로 자동 제외
   - 손가락 끝은 껍질 위에 있지만 직선을 이루지 않음
2. 순차 RANSAC으로 직선을 최대 4개 추출
   - 인라이어 허용 거리: `max(1.5px, 0.4% × sqrt(마스크 면적))`
   - 1200회 시도, 두 점 사이 최소 거리 12%, 최소 인라이어 수 8%
   - 전체 최소자승으로 3회 재피팅 후, 허용 거리의 3배 안의 점을 제거하고 다음 직선으로
3. 변 이름 붙이기
   - 마스크의 주축(PCA)을 긴 축으로 삼음
   - 긴 축과 28도 이내인 직선 중 중심의 좌·우에서 인라이어가 가장 많은 것이 좌변·우변
   - 긴 축과 50도 이상 벌어진 직선이 상변·하변
4. 변의 유효성: 직선 피팅 잔차가 폰 높이의 0.3% 미만이고, 길이가 폰 높이의 35%(좌·우) 또는 12%(상·하) 이상
   - 가려지거나 분할이 흔들린 변은 여기서 걸러져 해당 변을 쓰는 항목이 판단 불가가 됨

**중요**: 바깥 실루엣 4변은 후면 사각형이 아니다. 측면이 보이는 쪽은 프레임의 바깥 모서리(z = T)이고, 반대쪽은 후면 모서리(z = 0)다. 실루엣 네 모서리를 사각형에 대응시켜 펴면 틀린 답이 나온다. 반드시 6.6의 3D 모델을 거친다.

실패했던 방식: 행 단위로 첫 전경 픽셀을 찾는 방식(스킬의 `edges.py`)은 폰이 10도 이상 돌아가거나 손가락이 걸리면 깨졌다. 오피셜 이미지처럼 똑바로 선 깨끗한 렌더에는 지금도 유효하다.

### 6.4 원형 랜드마크(카메라, 센서) 검출

두 검출기의 결과를 합친다. 한쪽만으로는 놓치는 이미지가 있었다.

**검출기 1: 스케일 공간 + 경계 추적**

1. 폰 높이가 350px이 되도록 줄인 회색조에서 "본체 중앙값보다 어두운 정도" 맵을 만듦
2. `skimage.feature.blob_log` (σ 3~15, 13단계, 임계 0.03)로 어두운 원의 후보 위치와 대략적 반지름을 얻음
3. 각 후보에서 스킬의 `raycast_boundary`(240방향, 중심에서 바깥으로 가며 어두움 → 밝음 전환점 탐색)와 `trimmed_fit`(이상점 제거 타원 피팅) 적용
4. 통과 조건: 경계점 90개 이상, 반장축이 폰 높이의 1.6~7.5%, 장단축비 0.42 이상, 타원 바깥(1.35배)이 안쪽보다 30 이상 밝음

**검출기 2: 임계값 스윕**

1. 임계값 24~150을 6 간격으로 올리며 "어두운 픽셀"의 연결 성분을 구함
2. 볼록 껍질이 타원에 가까운 성분만 남김 (채움 비율 0.93~1.05, 볼록도 0.9 이상, 크기 폰 높이의 3~16%)
3. 같은 위치의 후보를 임계값 순으로 묶고, 면적 변화가 가장 작은 임계값의 것을 채택 (MSER과 같은 생각)

중심이 겹치는 것은 큰 쪽을 남긴다. 탐색 영역은 마스크의 볼록 껍질 내부다.

실패했던 방식: 고정 임계값(회색조 60 미만) 하나만 쓰는 방식은 노출이 다른 이미지 7장 중 5장에서 렌즈를 하나도 못 찾았다.

### 6.5 템플릿 매칭

검출된 원과 스펙의 원을 짝짓는다. 일부가 누락되거나 가짜 검출이 섞여도 동작해야 한다.

- 검출 k개를 스펙 5개에 대응시키는 모든 경우를 열거 (k는 5부터 2까지)
- 각 경우에 스펙 좌표 → 이미지 좌표의 아핀 변환(3점 이상) 또는 닮음 변환(2점)을 구해 채점
  - 변환 잔차 + 6 × 크기 불일치 + 0.5 × 외곽 불일치 + 2 × 버린 검출 수 + 1 × 빠진 스펙 수
- 제약: 뒤집힘 없음, 템플릿의 세로축이 폰의 긴 축과 50도 이내, 스케일이 폰 높이로 추정한 값의 0.6~1.35배

한계: 폰이 거꾸로 있거나 50도 이상 돌아간 구도는 대응이 실패한다. 180도 뒤집은 가설을 추가로 시험하도록 고쳐야 한다. 또한 원 5개와 그 크기 상수가 S26U에 맞춰 하드코딩되어 있다.

### 6.6 자세 추정 (Fit A)

스펙 템플릿을 그대로 두고 자세 6 + 초점거리 1을 맞춘다. 결과는 회전 정보, 렌즈 위치 잔차, 다른 피팅의 시작점으로 쓴다.

관측값과 잔차(모두 "예상 잡음" 단위로 정규화):

| 관측 | 모델 | 잡음 단위 |
|---|---|---|
| 원 중심 | 스펙 좌표(높이 포함)를 투영한 점 | max(0.7px, 폰 높이의 0.15%) |
| 원의 장단축비 | 시선과 면 법선의 내적 `|ray · n|` | 0.04 |
| 유효한 변 | 템플릿 변 위 두 점과 관측 직선 사이의 거리 | max(1px, 폰 높이의 0.2%) |

**실루엣 모델** (변 잔차의 핵심):

- 각 변에 대해 후면 모서리(z = 0)와 전면 모서리(z = T) 두 후보를 투영하고, **이미지에서 더 바깥에 있는 쪽**을 실루엣으로 선택
- **둥근 모서리 보정**: 프레임이 둥글어서 기울어질수록 실루엣이 각진 상자보다 안쪽에 온다. 변을 `ρ·(cos θ + sin θ − 1)`만큼 안쪽으로 옮긴다. θ는 해당 축 방향의 기울기, ρ = 2.2mm
  - 보정 전에는 사선 30도에서 폭이 약 2% 작게 재졌고, 보정 후 정답 이미지들이 W ±1%, H ±0.6% 이내가 됨

최적화:

- `scipy.optimize.least_squares`, 손실 `soft_l1`, `f_scale` 2.5, 최대 200회 평가
- 시작점 48개: 초점거리 {0.7, 1.4, 3, 8} × 이미지 폭, 좌우 기울기 {±0.25, ±0.6} rad, 상하 기울기 {-0.3, 0, 0.3} rad, 평면 내 회전은 긴 축 방향에서 계산
- 비용이 가장 낮은 해를 채택

### 6.7 회전 값 계산

- 전체 기울기: `arccos(|R[2,2]|)` (면 법선과 광축의 각)
- 좌우·상하 기울기: 폰 중심을 향하는 단위 시선 벡터를 폰 좌표계로 옮긴 `v = Rᵀ·(X_c/|X_c|)`에서 `atan2(|v.x|, |v.z|)`와 `atan2(|v.y|, |v.z|)`
- 평면 내 회전: 긴 축 방향 `u`에서 `atan2(−u.x, u.y)`

정면에 가까운 구도에서는 기울기가 ±10도 범위에서 구분되지 않는다(4.2절). 이 값을 그대로 믿으면 안 된다.

### 6.8 외곽 자유 피팅 (Fit B)

Fit A에 유효한 변마다 위치 오프셋(mm)을 미지수로 추가한다. 렌즈 군을 기준으로 본 몸체 크기 W, H와 불확실도를 낸다.

- 불확실도: `(JᵀJ)⁻¹ × max(1, χ²/자유도)`의 대각 성분
- 용도: "렌즈 군 대비 외곽 위치" 진단. 폰 전체가 균일하게 늘어난 경우는 이 값에 나타나지 않는다(4.2절)

### 6.9 종횡비 피팅 (Fit C)

사선 구도의 종횡비 항목이 쓰는 피팅이다. 자세 7에 **폭 배율 s**를 추가한다.

- 템플릿의 x 좌표(원 중심, 우변)와 원의 x 방향 지름에 s를 곱함
- 두께와 돌출 높이에는 s를 곱하지 않음. 이것이 기울임과 늘림을 구분하는 단서다
- 원의 장단축비 예측: 늘어난 원을 24점으로 투영해 공분산 고유값의 비로 계산
- 시작점: Fit A의 자세에서 s = {0.92, 1.0, 1.12}
- `s − 1`이 종횡비 편차이고, σ는 6.8과 같은 방식

이 피팅의 자세와 s로 항목별 값을 잰다.

- **위치**: 측정된 원 중심을 원이 놓인 평면(z = −높이)에 역투영해 mm 좌표를 얻고, x를 s로 나눈 뒤 스펙과의 차이를 폭·높이로 나눔
- **원형도**: 측정 장단축비 ÷ 예측 장단축비
- **크기**: 측정 장축 ÷ 예측 장축

### 6.10 측면 띠 피팅 (Fit T, 두께 기반)

렌즈를 쓰지 않고 측면 프레임 폭에서 기울기를 구하는 방식이다. 환경변수 `THICK=1`로 켠다.

1. 측면이 보이는 쪽 판별: 전면 모서리(z = T)가 더 바깥으로 투영되는 쪽
2. 안쪽 경계선(후면 유리와 프레임의 경계) 검출
   - 그 변의 높이 50~90% 구간에서 80개 위치를 잡음 (카메라와 버튼을 피하는 구간)
   - 각 위치에서 바깥 실루엣 직선으로부터 안쪽으로 프로파일을 뽑아(시작 10px, 블러 σ 2px) 밝기 변화가 가장 큰 지점을 선택
   - 이상점을 제거하고 직선 피팅
3. 자세 6 + s를 피팅. 관측은 유효한 바깥 변들 + 안쪽 경계선. 안쪽 경계선의 템플릿 위치는 `s·W − δ`(오른쪽) 또는 `δ`(왼쪽), δ = 0.5mm
4. **초점거리는 고정**한다. 현재 구현은 Fit A의 값을 물려받는데, 이것이 문제다(10장)

### 6.11 항목별 판정 (checks.py)

| 항목 | 계산 | 코드의 기준 | 합의된 수정 (코드 미반영) |
|---|---|---|---|
| 원 개수 | 측정된 원 + 존재 확인된 원 = 5, 추가 검출 없음 | 다르면 이상 | 그대로 |
| 종횡비 (정면) | `((상+하)/(좌+우)) ÷ (W/H) − 1` | 3% 초과 | 그대로 |
| 종횡비 (사선) | Fit C의 `s − 1` | 5% 초과이면서 3σ 초과 | **4σ**로 상향. 윗면·아랫면이 보이는 구도는 해당 변 제외 |
| 원 위치 | 가장 어긋난 원, 폰 높이 대비 | 1.5% (약 2.5mm) 초과 | 그대로 |
| 원형도 | 측정 ÷ 예측 − 1 의 평균 | 8% 초과 | **큰 원이 55px 미만이면 판단 불가** |
| 원 크기 | 측정 ÷ 예측 − 1 의 평균 | 15% 초과, 큰 원 55px 미만이면 판단 불가 | **큰 원에만 적용**, 작은 원은 참고값 |
| 모서리 R | 정면화한 마스크의 네 모서리 평균 | 25% 초과, 정면 구도만 | 그대로 |
| 플래시 위치 | 6.12 | 미구현 | **2mm**, 지름은 판정 제외 |
| 아일랜드 | 6.13 | 윤곽 검출 비율 90% 미만 | 그대로 |

**정면 구도 판별**: 4변이 모두 유효하고, 좌·우 변 길이 차 1.5% 미만, 상·하 변 길이 차 2% 미만, 측정된 원이 4개 이상이면 평균 장단축비 0.94 초과.

**존재 확인**: 타원을 정밀하게 재지 못한 스펙 원에 대해, 예상 위치의 안쪽(반지름의 0.35, 0.6, 0.8배)이 바깥(1.45배)과 본체 중앙값보다 25 이상 어두우면 "있음"으로 본다. 반사가 심한 렌즈의 검출 누락을 "누락"으로 오판하지 않기 위한 장치다.

**추가 검출**: 짝을 못 찾은 원 중 후면 내부(가장자리에서 5mm 이상 안쪽)에 있고 지름이 5~22mm인 것만 센다.

**모서리 R**: Fit A의 자세로 마스크를 후면 평면에 정면화(10px/mm)한 뒤, 각 모서리에서 대각선 방향으로 마스크에 닿을 때까지의 거리 g를 재고 `R = g / (√2 − 1)`로 환산한다.

### 6.12 플래시 검출 (flash.py)

1. Fit A의 자세로 후면 평면(z = 0)을 정면화. 창은 x 25~41mm, y 16~32mm, 20px/mm
2. Lab 색공간에서 주변 본체 색을 구함 (창 중심에서 3.3~4.5mm 떨어진 고리, 중심축 좌우 1mm 제외)
3. 본체 색과의 차이가 `max(4, 중앙값 + 5 × 잡음)`보다 큰 영역을 추출 (열림 5×5, 구멍 메움)
4. 창 경계에 닿지 않고, 지름 1.5~7mm이며, 창 중심에서 5mm 이내인 성분 중 가장 가까운 것을 채택
5. 중심 좌표, 등가 지름, 원형도를 출력

밝기가 아니라 색 차이를 보므로 본체 색에 상관없이 같은 식으로 동작한다. 창 위치는 S26U에 맞춰 하드코딩되어 있다.

### 6.13 카메라 아일랜드 검사 (island_crop.py, island_check.py)

1. Fit A의 자세로 카메라 영역을 **아일랜드 윗면 높이(z = −2.6mm)** 평면에 정면화. 창 50 × 72mm, 12px/mm
   - 이 높이에서 펴야 기울기와 무관하게 윤곽이 제자리에 온다
2. 스펙 윤곽(알약 모양)을 따라 140개 점을 찍음
3. 각 점에서 윤곽의 법선 방향 ±1.5mm 프로파일의 밝기 변화 최댓값을 구함. 측정된 원에서 0.6mm 이내의 표본은 제외
4. 배경 수준(평평한 본체 영역 x 30~48, y 44~60mm의 기울기 크기 90퍼센타일)의 3배를 넘으면 "경계 있음"
5. 경계가 있는 점의 비율이 90% 미만이면 이상

보조 신호: 검출된 경계가 스펙에서 떨어진 거리의 중앙값. 정상은 0.1~1.1mm, 다른 모양의 아일랜드(Failed_01)는 1.25mm였다.

## 9. 쓸 수 있는 방법과 쓸 수 없는 방법

### 9.1 동작이 확인된 방법

| 방법 | 용도 |
|---|---|
| 오피셜 이미지 + 실측 치수로 만든 mm 템플릿 | 기준 팩 |
| 볼록 껍질 위의 윤곽점 + 순차 RANSAC | 회전·가림에 견디는 외곽 검출 |
| 변별 직선 잔차로 유효성 판정 | 가려진 변을 자동으로 판단 불가 처리 |
| 스케일 공간 후보 + 경계 추적, 임계값 스윕의 결합 | 원형 랜드마크 검출 |
| 대응 가설 열거 + 아핀 채점 | 누락·가짜 검출에 견디는 매칭 |
| 바깥쪽 후보 선택 실루엣 모델 + 둥근 모서리 보정 | 측면이 보이는 구도의 자세 추정 |
| 폭 배율을 미지수로 둔 피팅 | 사선 구도의 종횡비 |
| 예상 위치의 어두움 검사 | 원의 존재 확인 |
| 자세로 정면화한 뒤 색 차이로 찾기 | 플래시 |
| 랜드마크 높이 평면에서 정면화 + 스펙 윤곽의 경계 검출 비율 | 아일랜드 |
| 측면 띠 폭으로 기울기 구하기 | 렌즈와 무관한 종횡비 (띠가 넓을 때) |

### 9.2 시험했으나 실패하거나 버린 방법

| 방법 | 실패 이유 |
|---|---|
| 호모그래피를 자유롭게 맞춘 뒤 비교 | 균일한 늘림을 그대로 흡수 |
| 자세 피팅 잔차로 종횡비 검사 | 5~10% 늘려도 잔차가 0.2%에 머묾 |
| "제품이 정상"이라는 가정으로 구한 기울기로 종횡비 계산 | 순환 논리 |
| 실루엣 네 모서리를 사각형에 대응 | 실루엣에 앞·뒤 모서리가 섞여 있음 |
| 행 단위 외곽 추출 | 회전·손 가림에 깨짐 |
| 고정 임계값 렌즈 검출 | 노출이 다르면 전혀 못 찾음 |
| 마스크 PCA로 회전 정규화 | 기울어진 마스크에서 10도 어긋남 |
| "없어야 할 곳의 경계" 검사 | 작은 원의 그림자를 경계로 잡아 정상에서도 61% |
| 오버레이의 두 사각형으로 두께 구하기 | 두께를 가정해서 그린 것이라 넣은 값이 나옴 |
| 렌즈 군 대비 몸체 크기(Fit B)로 늘림 검출 | 몸체와 렌즈가 함께 늘어나면 비율이 그대로 |
| Fit A의 초점거리를 측면 띠 피팅에 재사용 | 제품이 변형되면 초점거리가 오염됨 |

### 9.3 조사했으나 시험하지 못한 방법

SAM 계열 분할, 조밀 매칭(RoMa), 단일 이미지 캘리브레이션(GeoCalib, AnyCalib), 방향 추정(Orient Anything V2), VLM 체크리스트(Gemini), 영상의 다중 프레임 피팅. 이 환경에서는 가중치를 받거나 API를 호출할 수 없었다.

## 10. 제약, 한계, 알려진 문제

### 10.1 원리상의 한계

- 사선 구도에서 5% 미만의 균일한 종횡비 변형은 판단 불가다.
- 정면 구도의 종횡비는 3% 안팎이 한계다.
- 사선 구도에서 종횡비와 두께는 한 장으로 둘 다 정밀하게 검사할 수 없다.
- 사선 종횡비는 과소 추정된다 (16% → 12.3%).
- 판단 가능한 최소 편차가 이미지마다 다르다 (σ 1.0~4.3%). 결과에 이 값을 함께 내야 한다.

### 10.2 현재 구현의 알려진 문제

| 문제 | 영향 | 고칠 방향 |
|---|---|---|
| σ가 실제 오차보다 작다 | Test_04(+9.9 ± 3.3%), Test_17(-3.7 ± 1.0%)이 정상인데 3σ를 넘음 | 4σ 기준, 초점거리 민감도를 σ에 반영 |
| 윗면·아랫면이 보이는 구도가 미보정 | Test_04의 상단 변이 3.3mm 어긋남 | 해당 구도의 오피셜 이미지로 보정하거나 그 변을 제외 |
| 측면 띠 피팅이 초점거리를 물려받음 | Test_15가 +22.8 ± 14.1% | 이미지 전체에서 따로 추정하거나 대표값 + 민감도 범위 |
| 종횡비와 렌즈의 결합 | 렌즈 영역이 틀리면 종횡비 추정이 흔들림 | 측면 띠 방식과 대조 |
| 반사가 심한 큰 원을 놓침 | 4장에서 맨 위 원을 존재 확인으로만 처리 | 검출기 개선 또는 학습 기반 검출 |
| 원의 지름이 렌더링 방식에 좌우됨 | 정상에서 작은 원 +17%, 플래시 +18% | 지름 판정을 큰 원으로 한정 |
| 폰이 거꾸로이거나 50도 이상 돌아가면 매칭 실패 | 미시험 구도 | 180도 가설 추가 |
| 주점을 이미지 중심으로 가정 | 크롭된 이미지에서 어긋남 | 캘리브레이션 모델 또는 민감도 확인 |
| S26U 값이 코드에 하드코딩 | 다른 모델에 바로 못 씀 | 스펙 파일로 분리 (5.3절) |
| 사선 종횡비 피팅이 느림 | CPU에서 장당 1~2분 | 해석적 야코비안, 시작점 축소, 사선 구도에만 실행 |
| 큰 변형에서 피팅 실패 | 대조 실험에서 16% 늘린 Good_02가 엉뚱한 해로 감 | χ²가 크면 판단 불가로 처리 |
| 아일랜드 검사가 흐린 경계에 민감 | 경계 기준을 높이면 Good_02가 80% | 이미지별 대비에 맞춘 기준 |
| 덧그려진 판, 아일랜드 없는 모델 | 현재 방식으로 못 잡음 | VLM 체크리스트 |

### 10.3 검증의 한계

- **블라인드 평가를 하지 않았다.** 모든 기준은 이 문서의 이미지를 보면서 정했다.
- 생성 이미지는 14장, 모델은 1개, 색상별 생성 이미지는 1장씩이다.
- 분할 박스는 모두 사람이 줬다.
- 정답이 있는 합성 평가셋은 만들지 않았다.
- 전면, 측면 구도, 영상, 다른 제품군은 시험하지 않았다.
- 미묘한 실패 사례(정면 구도의 작은 비율 오류, 렌즈 간격 오류)는 표본이 없다.

## 11. 서비스 구현 시 권고

### 11.1 구조

```
입력 이미지
  → [1] 제품 영역 분할           (교체: 프롬프트 기반 분할 모델 + 사용자 확인)
  → [2] 정규화
  → [3] 외곽 검출, 원형 랜드마크 검출, 매칭
  → [4] 자세 추정 (Fit A)
  → [5] 구도 판별 → 정면: 직접 측정 / 사선: 종횡비 피팅 (Fit C), 측면 띠 (Fit T)
  → [6] 항목별 측정 (위치, 원형도, 크기, 모서리 R, 플래시, 아일랜드)
  → [7] 정면화된 크롭을 VLM 체크리스트에 전달   (신규: 형상·외형 판단)
  → [8] 항목별 3값 판정 + 감사용 오버레이
```

### 11.2 PoC에서 임시로 처리해 교체해야 할 부분

1. **분할**: 손으로 준 박스 + GrabCut + 피부색 제거 → 프롬프트 기반 분할 모델. 측정 품질이 마스크 경계에 직접 좌우된다.
2. **초점거리**: 제품 피팅에서 얻지 말고, 배경을 포함한 이미지 전체에서 추정하거나 대표값을 쓰고 범위(예: 이미지 폭의 1.0~2.0배)에서 결과가 어떻게 변하는지 함께 낸다.
3. **속도**: 종횡비 피팅은 수치 미분과 다중 시작점 때문에 느리다. 정면 구도에서는 실행하지 않는다.
4. **스펙 분리**: 원 5개, 지름, 높이, 플래시 창, 아일랜드 윤곽이 코드에 박혀 있다.

### 11.3 추가할 층: VLM 체크리스트

기하 층이 구한 자세로 카메라 영역을 정면화하면, 오피셜 이미지의 같은 영역과 같은 시점으로 정렬된 한 쌍이 된다. 이 쌍을 VLM에 주고 좁은 질문을 한다.

- 아일랜드가 큰 원 3개만 감싸는가, 다른 판이 덧그려지지 않았는가
- 센서 자리에 카메라처럼 생긴 것이 그려지지 않았는가
- 로고 글자가 맞는가
- 버튼이 없어야 할 쪽에 버튼이 있는가

이번 PoC에서 Test_06을 처음 알아본 것은 사람 눈과 같은 방식의 판단이었고, 측정은 통과시켰다. 반대로 VLM 계열은 미세한 차이와 개수에 약하다는 연구가 있으므로 측정값과 교차 확인한다.

### 11.4 출력 형식 제안

```json
{
  "item": "aspect_ratio",
  "status": "pass | fail | not_judged",
  "measured": 0.123, "expected": 0.0,
  "sigma": 0.013, "tolerance": 0.05, "min_detectable": 0.052,
  "method": "fitC", "view": "oblique",
  "reason": "편차가 5%와 4σ를 모두 초과"
}
```

모든 판정에 감사용 오버레이(검출된 변, 투영된 템플릿, 측정된 원)를 붙인다. PoC에서 수치만 보고 놓친 문제를 오버레이에서 여러 번 찾았다.

### 11.5 영상

프레임마다 자세는 변해도 제품 형상은 같아야 한다. 여러 프레임을 한 번에 맞추면 늘어남과 기울임이 분리될 것으로 예상한다. 시험하지 않았다.

### 11.6 평가

1. 지금 기준을 고정하고, 라벨을 가린 새 이미지 20~30장으로 블라인드 평가
2. 오피셜 이미지를 알려진 카메라로 변형하고 결함을 주입한 합성 평가셋 제작 (결함 크기별 검출 곡선)
3. 검수자 2명의 독립 라벨로 "사람이 봐도 이상한 수준"의 기준 확정

PoC 코드를 실행한 상태 그대로 담았다. 서비스 코드가 아니라 **알고리즘 참조용**이다.

### 12.1 구성


### 12.2 스킬과 파이프라인의 관계

- `pipeline3.py`는 스킬의 `ellipses.py`에서 `raycast_boundary`와 `trimmed_fit` 두 함수만 가져다 쓴다.
- `ref.py`는 스킬의 `edges.py`로 뽑은 오피셜 후면 외곽(`back_obs.json`)을 입력으로 쓴다.
- 스킬의 뷰 유형 판별표와 "실루엣 네 모서리로 펴지 말 것"이라는 주의사항이 4.2절과 6.3절의 출발점이다.
- 스킬은 깨끗한 렌더와 사진을 전제로 한다. 생성 이미지의 회전·가림·저해상도 때문에 외곽 검출과 자세 피팅은 새로 작성했다.

### 12.3 실행 순서

`poc/` 폴더에서 실행한다. 이름이 `X`인 이미지 기준이다.

```bash
# 0. 분할: 이미지를 보고 박스를 정한 뒤 실행 (자동 감지 없음, 자세한 절차는 product_qa_runbook.md)
python grid_preview.py /path/IMAGE.png grid.jpg        # 격자에서 박스 좌표(원본 픽셀)를 읽음
python segment.py /path/IMAGE.png X X0 Y0 X1 Y1        # → X_rgba.png, X_seg_preview.jpg (반드시 열어서 확인)
python prep.py X                                       # → n_X_rgba.png, n_X_meta.json

# 1. 자세와 측정, 오버레이
FAST=1 python pipeline3.py overlay.jpg X     # Fit A만 (약 30~40초)
python checks.py X                           # 전 항목 판정 → res_X.json (사선 구도는 1~2분)

# 2. 플래시, 아일랜드
python flash.py X                            # → flash_X.json, flash_X.jpg
python island_crop.py X                      # → isl_X.png, isl_X.json
python island_check.py X

# 3. 측면 띠 방식 (선택)
FAST=1 THICK=1 python thick.py X
```

환경변수:

| 변수 | 효과 |
|---|---|
| `REF_PACK=파일` | 기준 팩 선택. 기본값은 `ref_back.json` (S26 Ultra) |
| `FAST=1` | Fit B와 Fit C를 건너뜀 |
| `THICK=1` | 측면 띠 피팅 실행 |
| `F_OVER_W=1.3` | 측면 띠 피팅의 초점거리를 이미지 폭의 배수로 지정 |
| `PROFILE=1` | 종횡비 값별 비용 곡선 계산 |
| `DROP_REF=0` | 스펙 원 하나를 빼고 실행 (민감도 실험용) |

### 12.4 의존성

Python 3.12, OpenCV 5.0.0, NumPy 2.5.4, SciPy 1.18.1, scikit-image 0.26.0에서 실행했다. GPU는 쓰지 않는다.

### 12.5 코드를 읽을 때 주의할 점

- `ref.py`의 입력 경로는 하드코딩되어 있다. 이전 판의 `segment_grabcut.py`(박스가 코드에 고정)는 `segment.py`로 대체했다.
- 기준 팩의 본체 두께, 원 지름, 원 높이, 모서리 R은 팩 JSON에 `T`, `d_big`, `d_small`, `h_big`, `h_small`, `corner_R` 키가 있으면 그 값을, 없으면 S26 Ultra 값을 쓴다.
- `checks.py`의 기준값은 6.11절 "코드의 기준" 열과 같다. 합의된 수정은 반영하지 않았다. `results/`의 JSON이 이 코드로 나온 값이기 때문이다.
- `ref_back.json`의 여섯 번째 항목은 잘못 검출된 것으로, 코드에서 걸러진다.
- `island_score.py`의 `__main__`은 초기 버전의 스펙 탐색과 버린 검사(없어야 할 곳의 경계)를 포함한다. 최종 채점은 `island_check.py`다.
- 한 파일에 여러 실험이 누적되어 있어 정리가 덜 되어 있다. 서비스 코드는 6장의 설명을 기준으로 새로 작성하고, 첨부 코드는 수치와 동작을 대조하는 용도로 쓰는 것을 권한다.

## 13. 미결 사항

1. 블라인드 평가 (11.6절)
2. 합의된 기준 수정의 코드 반영과 재검증 (6.11절)
3. 초점거리 독립 추정
4. 윗면·아랫면이 보이는 구도의 보정
5. VLM 체크리스트 층 시험
6. 측면 띠 방식과 렌즈 방식의 결합 규칙 (일치하면 불확실도 결합, 어긋나면 신호로 사용, 띠가 10px 미만이면 미사용)

9. 로고가 보이지 않는 이미지를 이상으로 볼지에 대한 기준
