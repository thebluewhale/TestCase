# 영상 후보 시간 경계 처리 및 표시 정밀도

2026-11-06 사용자 결정. 구현 정책 `video-boundary-clamp-0.33s-v1`.

## 구현

후보의 시작·종료 시각을 원본 영상 시간축에서 검증한다.
- 시작이 0초보다 앞서도 초과량이 0.33초 이내이면 0초로 보정한다.
- 종료가 영상 끝보다 뒤여도 초과량이 0.33초 이내이면 실제 영상 끝으로 보정한다.
- 양쪽 초과량을 각각 확인한다. 0.33초 경계의 부동소수점 계산 오차에만 1e-12초를 허용한다.
- 내부 구간의 시각은 바꾸거나 프레임에 맞춰 반올림하지 않는다.
- 초과량이 더 크거나, 비유한 수·잘못된 타입·일부 null·역전·길이 0이면 거부한다.
- 보정 후 영상과 겹치는 양의 길이 구간이 없으면 거부한다. 완전히 영상 밖인 후보를 만들지 않는다.
- 이미지 시간 null, 영상 위치 미상 사유, bbox 검증 및 좌표 오류 1회 재시도는 유지한다.

0.33초는 FPS와 무관한 절대 시간 허용오차다. 30fps에서는 약 10프레임에 해당한다.
가변 FPS와 원본 PTS는 그대로 사용한다. 이것은 경계 밖 좌표를 수용하는 규칙이지,
모델이 제시한 사건 시각 전체의 정확성을 보증하거나 R–C 시간 차이를 성공 조건으로 삼는 규칙이 아니다.

`provenance.time_boundary_correction`에 정책·허용오차·영상 길이·원본 구간·보정 구간·변화량·사유를
기록한다. 호출자의 입력을 수정하지 않으며 모델 원문 응답도 보존한다. 정상 입력은 보정 기록을 만들지 않는다.
정확 중복 병합 후에도 개별 원본의 보정 이력은 source_records에 남는다.
Gemini 모델 결과에도 정책명과 허용오차를 기록한다.

## 사람용 표시

HTML·TXT의 구간, 프레임 시각, 브라우저 영상 길이 및 검수/비교 CSV의 시간값은 소수점 3자리다.
예: `4.083–4.583초`. 기존 60개 검수 페이지 2곳에도 표시만 적용하고 이전 표시 파일을 백업했다.
원문 설명 안의 숫자를 임의로 고쳐 쓰지는 않는다. 원본 JSON·내부 계산·영상 재생 위치는 정밀도를 유지한다.
숫자 표시 함수는 계산이나 검증 입력으로 사용하지 않는다. JSON 다운로드는 감사용 원본 데이터다.
기존 후보 피드백 CSV는 예전 원본 시간 표기와 새 3자리 표기를 모두 검증해 받을 수 있다.

## 실제 저장 응답 재검증

새 원격 호출 없이 기존 Gemini 응답을 현재 수신·검증 경로로 재생했다.
원본 보고서 해시·영상 해시·요청 해시·모델 응답 원문을 대조했고 기존 60개 평가 결과를 변경하지 않았다.

| 영상 | 기존 오류 | 새 검증 결과 |
|---|---|---|
| sid_022_seedance | 종료 5.042초 > 영상 5.041666…초 | 전구 변형 후보 1개 정상 수용 |
| sid_045_seedance | 같은 종료 경계 초과 | 후보 2개 정상 수용 |
| sid_195_seedance | 같은 종료 경계 초과 | 시간 오류는 해소됐으나 별도 bbox 오류로 계속 거부 |

sid_195_seedance의 bbox는 `[0.697, 0.0, 0.896, 5.042]`다. 이 값은 공간 좌표 계약 위반이며
시간 허용오차로 정당화하지 않는다. 오프라인 재생에서는 동일한 저장 응답을 두 번 반환해
기존 좌표 재시도 한도까지 검증했다. 실제 새 모델 응답을 요청한 결과는 아니다.

검증 자료는 `work/time_boundary_033_20261106/`, 검토용 사본은
`~/TestCase/anomaly_benchmark/time_boundary_033_20261106/`에 보관한다.
[검증 JSON](time_boundary_validation_20261106.json).

전체 테스트 **314개**, Ruff, 다른 anomaly 버전과의 독립성 검사를 통과했다.
시간 경계 안팎·빈 구간·원문 불변·정밀도 유지·보정 이력·좌표 가드·CSV 내보내기를 검증했다.
이 검증은 후보 수신 처리의 복구이며, 새 검출 성능 평가나 라벨 hit 인정은 아니다.
