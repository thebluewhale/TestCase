# 사건 의미 매칭 v3 — 구현 및 검증

2026-11-05. 평가기 버전은 `event-claims-3`이며 서비스 디렉토리는 계속 `review_anomaly_v4`다.
이 문서의 v3는 서비스의 이전 버전 `review_anomaly_v3`와 관계없는 **매칭 평가기 계약 버전**이다.

## 구현한 판정 기준

- 주 지표는 원본 라벨의 이상 증상 하나 이상을 의미상 포착한 영상 수다. 영상당 최대 1회 집계한다.
- 시간 구간은 사전 후보 필터나 hit 게이트로 쓰지 않는다. 시간 차이·누락·오류만으로 hit를 취소하지 않는다.
- 라벨 밖 결함이나 일반적인 측정 제안에 성공을 부여하는 경로를 추가하지 않았다.
- 미완료 탐지/평가, 실제 의미 대응의 불확실성, 원본 라벨 없음은 여전히 보류 가능하다.
- 기존 v2 결과와 캐시는 보존한다. 새 요청·응답 계약과 버전이 다르므로 v2 캐시를 v3로 사용하지 않는다.

## 라벨 증상 분해와 대응 근거

각 R의 자동 해석 결과에 `claims`를 추가했다. `R1.S1`, `R1.S2`처럼 원본 R 아래의 식별자를 사용한다.
각 항목은 원문 그대로의 `evidence`, `symptom_ko`, `is_anomaly`를 가진다. 최대 8개이며 식별자 순서·
중복·원문 부분 문자열 여부·타입을 검증한다. 배경 설명이나 정상 행동만 있는 항목은 이상 증상으로
승격하지 않는다. 이 분해는 새 정답 작성이나 원본 수정이 아닌 자동 해석 기록이다.

각 R/C 쌍은 `reference_claim_ids`로 판단 대상 증상을 지정한다. 긍정 관계에는 실제 이상 주장인
증상, 해당 증상에서 복사한 원문 근거, 후보 원문 근거, 공통 사건 설명이 모두 필요하다.
없는 증상, 다른 R의 증상, 후보에만 있는 증상, 임의로 만든 인용문은 거부한다.
원본의 복합 라벨 전체와 모든 후보가 일치할 필요 없이 하나의 유효 증상 대응으로 영상 hit가 가능하다.

`target_relation=same_interaction`은 동일한 구체적 상호작용/객체 전환을 참가자·물체 또는
부분·전체 관점에서 설명하는 경우다. 같은 물체/장면/행동 종류만으로는 충분하지 않으며
`shared_event_ko`와 양쪽 원문 근거가 필요하다. 다른 사람·다른 대상에 대한 설명을 결합하지 않는다.

## 설명 차이의 범위

`description_consistency`와 별도로 `conflict_scope`를 저장한다.

| 범위 | 처리 |
|---|---|
| `none` | 설명 충돌 없음 |
| `peripheral` | 부수적 차이로 보존, 유효한 공통 증상을 자동 탈락시키지 않음 |
| `other_claim` | 선택하지 않은 다른 증상의 차이로 보존 |
| `matched_claim` | 대응시키려는 핵심 증상 자체의 모순. 긍정 집계 제외 |
| `uncertain` | 충돌 범위를 확정할 수 없음. 긍정 집계 제외 |

의미 관계가 긍정이고 대상이 같거나 같은 구체적 상호작용이며, 핵심 증상 충돌/근거 부족이 없을 때
대응을 인정한다. 부분 대응에 불필요한 라벨의 다른 주장을 함께 강제하지 않는다.
텍스트의 주장 비교이며 영상의 사실 정확성이나 의도를 검증한 것으로 표시하지 않는다.

## 시간 보조 표시

| 상태 | 표시 기준 |
|---|---|
| 시간도 일치 (`aligned`) | 두 구간이 유효하고 IoU ≥ 0.1 |
| 시간 차이 있음 (`different`) | 두 구간이 유효하고 IoU < 0.1. 인접·분리 구간 포함 |
| 시간 비교 불가 (`unavailable`) | 시각 누락, 잘못된 구간, 비유한 값 등 |

0.1은 기존 비교를 이어 보기 위한 **표시 경계**일 뿐 hit 임계값이나 확률 신뢰도가 아니다.
`localized_video_hit`, IoU·간격·포함률·오차는 과거 비교용 진단 필드로 보존하고
주 지표인 `stage1_automatic_hits`와 구분한다. 실제 반복 사건의 식별이 모호한 경우의 보류는
시간 차이가 아니라 의미 근거의 불확실성에 따른다.

## 출력과 실행

HTML의 주 표는 기존 v1 자동 결과, 새 의미 대응 hit, 시간 보조 표시, 판정 상태를 보여준다.
상세 표에는 라벨별 증상 근거와 대응한 증상 ID, 설명 차이 범위를 함께 표시한다.
`claims.csv`는 원본 R ID·원래 문장·자동 분해 근거를 추적하는 추가 출력이며,
`videos.csv`, `pairs.csv`, `scorecard.json`도 새 계약을 포함한다.

```bash
# v4 디렉토리에서 실행. 신규 출력 폴더를 사용한다.
.venv/bin/python -m review_anomaly_v4.event_evaluation \
  --source work/flash_development60_resumed_20261105 \
  --output work/event_claims3_new
```

선택 검증은 `--asset-id`를 반복한다. v3 자체의 성공 결과는 `--resume`으로 재사용할 수 있다.
인증 중단만 재개할 때 `--resume --retry-auth`, 저장된 응답 형식 오류 재시도는 `--resume --retry-invalid`다.
모델은 Vertex AI `gemini-3.8-flash`만 사용한다. 사람 검수 파일은 선택적인 사후 진단 입력이며
모델의 의미 판단 입력으로 보내지 않는다. 탐지 호출 없이 동결된 R/C 설명만 평가한다.

## 검증 범위

전체 회귀 테스트 **216개**, Ruff, 다른 anomaly 서비스 버전과의 독립성 검사 통과.
새로 검증한 항목은 복합 라벨의 부분 증상, 다른 증상과 핵심 증상 충돌의 분리,
시간 차이/누락/오류/과도하게 넓은 구간의 hit 독립성, 라벨 밖/정상 맥락 제외,
존재하지 않거나 다른 R에 속하는 증상 ID 거부, v2 캐시 거부, HTML/CSV 근거 표시다.

실제 데이터 검증은 사람이 확인한 라벨 대응 6개와 라벨 밖/다른 인물 사례 4개를 별도로 선택했다.
원본 라벨과 후보 ID를 실행 결과와 대조해 `work/event_claims3_review6_20261105.json`에
사람 보정 근거를 보존했다. 이 10개는 개발 검증이며 독립 정확도나 전체 60개 성능이 아니다.
실제 호출 결과는 아래에, 기계 판독용 기록은 [event_matching_v3_validation.json](event_matching_v3_validation.json)에 보존한다.


## 실제 개발 사례 검증 결과

최종 프롬프트로 Vertex AI `gemini-3.8-flash`를 호출해 선택한 10개 모두 채점을 완료했다.
동결된 탐지 결과를 재사용했고 영상 탐지 호출은 0회다. 사람 검수의 6개 그룹 모두 지정한
R–C 묶음 안에 유효한 대응이 나왔다. 묶음의 모든 조합을 성공하도록 강제하지 않았다.

| 영상 | 지정 그룹에서 인정한 대응 | 시간 보조 상태 | 영상 상태 |
|---|---|---|---|
| sid_013_seedance | R2 ↔ C1, C4 | 차이 있음 | hit |
| sid_013_veo3 | R2 ↔ C1, C3 / R3 ↔ C1, C3 | R2 일치 / R3 차이 있음 | hit |
| sid_040_seedance | R1 ↔ C1, C3 | 차이 있음 | hit |
| sid_090_ltx2 | R2 ↔ C2 | 차이 있음 | hit |
| sid_172_seedance | R2 ↔ C2 | 차이 있음 | hit |
| sid_173_seedance | R1 ↔ C2 | 일치 | hit |

sid_040_seedance는 지정 그룹 밖의 **기존 원본 라벨** R2와 C1/C3도 대응했다.
라벨 밖 관측을 성공 근거로 삼지 않는지 확인한 sid_069_ltx2·sid_198_ltx2는 no_hit,
sid_176_ltx2는 의미 불확실성이 남아 pending이었다. 다른 인물을 잘못 연결하지 않는지 본
sid_141_seedance는 의미 대응 없음·기존 탐지 미완료로 pending이었다. 이 4개 모두 의미 hit가 없었다.
보류를 확정 음성으로 세지 않으며 이 표본으로 정밀도나 85% 목표 달성을 추정하지 않는다.

첫 개발 실행에서는 sid_173_seedance가 지정한 도구 출현 대신 손잡이 후보와 다른 라벨로
성공했고, sid_176_ltx2에서 벽을 만지는 행동과 얼굴 왜곡을 과도하게 연결했다.
이에 공유 행동만으로 연결하지 않는 제약과 새 도구 출현의 핵심/부수 위치 차이 구분을
프롬프트에 보완한 뒤 **10개 전부 새 요청 해시로 다시 호출**했다. 개별 영상 ID 조건은 없다.
이 과정에서 사용한 사례이므로 결과는 개발 보정 검증이며 독립 검증이 아니다.

- 초기 개발 응답: `work/event_claims3_smoke10_20261105/` (보존)
- 최종 개발 응답·HTML·CSV: `work/event_claims3_smoke10_refined_20261105/`
- 사람 대응 원문/후보 ID 고정: `work/event_claims3_review6_20261105.json`
- 열람용 복사본: `~/TestCase/anomaly_benchmark/event_matching_v3/`

전체 60개의 v3 재채점, 미사용 SID 그룹의 독립 평가, 85% 목표 달성 확인은 아직 수행하지 않았다.
기존 v2의 26/60·의미 진단 30/60을 이번 버전 성능으로 바꾸어 표기하지 않는다.
