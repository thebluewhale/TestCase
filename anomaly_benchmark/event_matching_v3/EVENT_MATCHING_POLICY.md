# 사건 의미 매칭 — 최신 평가 기준과 구현 상태

최종 정리: 2026-11-05, 기존 60개 재채점 이후 사용자 합의.

**상태: 아래 기준을 `event-claims-3`에 구현했다. 전체 회귀 테스트 216개를 통과했다.**
현재 hit는 원본 라벨의 의미 대응으로 판단하고 시간은 보조 표시만 한다. v2는 과거 결과로 보존한다.
구현 계약과 실제 검증 범위는 [v3 구현 기록](EVENT_MATCHING_V3.md)을 참조한다.
기존 코드/결과는 [v2 구현 기록](EVENT_MATCHING_V2.md),
[60개 재채점 기록](EVENT_MATCHING_V2_60_RESULTS.md)에 보존한다.
평가기 판정 기준에 대한 후속 결정을 이 문서에서 관리하고 SDP·SDD와 연결한다.

## 1. 성공의 정의와 제외 범위 — 확정

**영상에서 원본 정답 라벨에 적힌 이상 현상 하나 이상을 의미상 포착한 유효 후보가 있으면 `hit`이다.**
하나의 영상은 한 번만 성공으로 센다. 사전 고정한 전체 N개 중 H/N ≥ 85%라는 1단계 목표를 유지한다.
미완료·보류 영상도 전체 분모에서 제거하지 않는다. 자동 판정과 사람 확인의 출처를 구분한다.

- 원본 라벨에 없는 결함은 사람이 실제 현상으로 확인했더라도 이번 성공 집계에 넣지 않는다.
- 기존 사람 관측 메모는 이력으로 보존할 수 있지만 새 정답 라벨로 자동 편입하거나,
  라벨 대응과 합쳐 성공 수를 늘리는 별도 인정 경로를 구현하지 않는다.
- 라벨 오류·누락이 의심돼도 평가 중 원본 라벨을 임의 수정하지 않는다.
- 같은 장면·물체·결함 종류를 언급했다는 이유만으로 의미 대응을 인정하지 않는다.
- 일반적인 “변화 가능성” 제안은 구체적 라벨 증상을 포착한 설명으로 승격하지 않는다.

## 2. 시간은 보조 상태 — 확정

사용자는 원본 라벨 timestamp의 신뢰도가 높지 않다고 판단했다.
시간 겹침·IoU·시작/끝 오차를 **hit의 필수 조건과 의미 비교 후보의 사전 필터에서 제외**한다.

| 표시 | 역할 |
|---|---|
| 시간도 일치 | 의미 대응을 뒷받침하는 참고 정보 |
| 시간 차이 있음 | 라벨과 후보의 시각이 다름을 알리는 정보. 이것만으로 hit를 취소하지 않음 |
| 시간 비교 불가 | 시각 누락·잘못된 구간 등으로 비교할 수 없음. 의미 판단과 별도 기록 |

- 의미가 명확하게 대응하면 시간이 달라도 hit으로 판정한다.
- 의미가 모호하면 시간이 겹쳐도 자동으로 hit이 되지 않는다.
- 의미가 다르면 시간이 같아도 불일치다.
- 동일 현상이 반복돼 어느 사건을 가리키는지 실제 의미 대응이 불확실하다면 보류할 수 있다.
  단순한 시간 차이 자체와 사건 식별의 불확실성은 구분한다.
- IoU를 대응 신뢰도 확률로 환산하지 않는다. 사용자가 선택한 방식은 보조 상태 표시다.
- 원시 시각·IoU·간격 등은 진단용으로 보존한다. 두 구간이 유효하고 IoU ≥ 0.1이면 시간도 일치,
  그 미만이면 시간 차이 있음, 누락·오류 구간이면 시간 비교 불가로 표시한다. 이 경계는 hit에 영향을 주지 않는다.

## 3. 의미 매칭 개선 — 구현 완료

### 라벨의 개별 증상 비교

한 R에 여러 증상이 기술되면 원문을 보존하면서 원문에 명시된 이상 주장 단위로 구분한다.
C가 그중 하나를 구체적으로 설명하면 대응 근거로 인정한다. 단순한 동작·장면 설명을
이상 증상으로 새로 만들거나, 라벨 전체의 모든 내용을 설명하도록 요구하지 않는다.
원본 R ID와 해당 근거 구절까지 추적할 수 있어야 한다.

예: “양상추가 떨어지는 방식이 비현실적이며 당근이 갑자기 나타남”에서
그릇 안 채소의 자발적 출현을 설명하는 후보는 출현 증상에 대한 대응 근거가 될 수 있다.
대상 표현의 상위·하위 범주 차이는 공통 사건 근거와 함께 판단한다.

### 공통 사건과 설명 차이 분리

같은 사건의 다른 측면·부분 묘사를 인정하되 양쪽 원문에 구체적 공통 이상 사건의 근거가 필요하다.
공통 사건과 관계없는 부수적인 설명 차이로 전체 대응을 무효화하지 않는다.
대상 인물·물체 또는 공통 핵심 현상 자체가 다르거나 모순되는 경우에는 자동 성공을 강제하지 않는다.
텍스트만으로 확인할 수 없는 대응은 보류/사람 확인 대상으로 남긴다.
영상 확인이 필요한 사례가 있다는 사실을 전체 텍스트 매칭 기준을 느슨하게 할 이유로 삼지 않는다.

### 영상 단위 한 번 집계

어느 하나의 유효한 R–C 대응으로 영상 성공을 판단한다. 여러 R/C의 관계는 보존하되,
사용자가 같은 증상으로 묶었다는 이유로 모든 R×C 조합을 각각 정답으로 확장하지 않는다.
부수적인 설명 정확성과 위치 유용성은 별도 기록한다. 텍스트 간 양립 여부를 영상 사실 검증으로
표시하지 않는다.

## 4. 후속 사람 검수에서 제시한 보정 사례

다음 6개는 사용자가 원본 라벨과 후보가 같은 증상을 포착했다고 확인한 개발 보정 사례다.
영상 단위 대응을 검증할 때 사용하며 ID별 고정 정답 처리나 탐지 프롬프트 입력으로 사용하지 않는다.
실제 R/C 번호·원문은 해당 실행의 동결 결과와 대조한 뒤 사용한다.

| 영상 | 확인하려는 대응 |
|---|---|
| sid_013_seedance | 라벨의 갑작스러운 생성 ↔ 그릇 안 채소의 자발적 생성 |
| sid_013_veo3 | 특히 라벨의 재료들이 달라붙는 현상 ↔ 층층이 쌓여 뭉친 형태 |
| sid_040_seedance | 청소 전환 중 손·도구의 이상 현상에 대한 라벨과 후보의 대응 |
| sid_090_ltx2 | 라벨과 후보의 손 구조·상호작용 이상 대응 |
| sid_172_seedance | 빙벽 도구 길이 변화. 시간 차이만으로 성공을 배제하지 않음 |
| sid_173_seedance | 도구의 교체·출현 사건에 대한 라벨과 후보의 대응 |

별도로 제시됐던 sid_069_ltx2·sid_176_ltx2·sid_198_ltx2의 **라벨 밖 관측**은 성공 근거로 사용하지 않는다.
sid_173_seedance의 라벨 밖 C3도 이 성공 근거에서 제외한다.
이는 해당 영상의 모든 후보를 금지한다는 뜻이 아니라, 라벨 밖 관측을 정답으로 승격하지 않는다는 뜻이다.

## 5. 구현 상태와 후속 검증

- `event_matching.py`: 프롬프트·응답 계약에 개별 증상 근거와 공통 사건/부수 차이 구분을 반영했다.
  `score()`의 최종 hit 조건에서 시간 게이트를 제거하고 보조 상태를 분리했다.
- `event_evaluation.py`: 주 지표를 원본 라벨의 의미 대응으로 보고하고 시간은 보조 상태로 출력한다. `claims.csv`에 증상별 원문 근거를 추가했다.
- 회귀 검증: 위 보정 사례, 복합 라벨의 부분 포착, 같은 물체지만 다른 현상, 다른 인물,
  일반 측정 후보, 반복 사건의 모호함, 시간 차이·누락·오류, 중복 집계 방지를 포함한다.
- 새 버전 `event-claims-3`를 부여하고 프롬프트·응답 계약·캐시·리포트를 구분했다.
  v2 판단 캐시를 새 의미 알고리즘의 응답으로 재사용하지 않는다.
- 같은 탐지 결과를 새 버전으로 재채점하며 영상 탐지를 다시 실행할 필요는 없다.
  사람 사례는 보정/진단에만 사용하고 기존 60개를 독립 검증 자료로 부르지 않는다.
- 새 SID 그룹의 불일치·경계 사례 검증은 별도의 후속 작업이다.

## 6. 기존 결과와 새 기준의 구분

v2 전체 60개 결과는 기존 자동 대응 17/60, v2 의미·시간 포함 대응 26/60,
v2 의미 대응 진단 30/60이다. 이 숫자는 당시 기준의 기록으로 보존한다.
**30/60은 v2의 진단값이며 v3 구현의 평가 결과로 바꾸어 발표하지 않는다.**
v3 구현·소규모 개발 검증과 전체 60개 재채점·독립 검증·85% 목표 달성은 별개다.
전체 60개의 v3 재채점과 독립 사례 검증은 후속 작업으로 남아 있다.
