# 벤치마크 집계 v2 — 의미 대응·검출 실행·채점 유효성 분리

2026-11-12. 구현 완료. 의미 평가 계약은 `event-claims-6` 그대로이며, 집계 계약만 `event-aggregation-2`로 분리했다.
검출기·원본 R·C·의미 일치 기준·시간 보조 기준은 변경하지 않는다. 실제 사용자 검수 경로에서 이 매칭/집계를 실행하지 않는다.

## 독립 상태와 영상 판정

| 필드 | 상태 | 의미 |
|---|---|---|
| `semantic_status` | matched / not_matched / pending | 유효한 R–C 대응 있음 / 모두 평가했으나 대응 없음 / 판단 근거 불완전·불확실 |
| `detection_execution_status` | completed / partial / failed / not_run / unknown | 전체 완료 / 일부 결과 있음 / 실행 실패 / 미실행 / 기존 기록의 실행 근거 부족 |
| `evaluation_validity` | valid / partial / invalid / not_run | 필요한 채점 전체 유효 / 일부 독립 쌍만 유효 / 활용할 유효 쌍 없음·검증 실패 / 채점 미실행 |

- 유효한 원본 R–C 대응이 하나라도 있으면 **hit**이다. 검출 일부 실패나 다른 쌍의 채점 실패는 함께 표시하며 이 대응을 취소하지 않는다.
- **no_hit**은 검출 전체 완료, 필요한 채점 전체 유효, 원본 R 존재, 의미 불확실성 없음, 대응 없음의 조건을 모두 만족해야 한다.
- 그 외는 **pending**이다. 의미 대응 없음(`not_matched`)과 최종 pending이 동시에 가능하다.
- 전체 N과 85% 목표는 유지한다. 실패·보류를 분모에서 제외하지 않는다. 라벨 밖 결함·일반 측정 제안은 hit으로 인정하지 않는다.
- 시간 겹침·차이·비교 불가는 보조 정보다. `localized_video_hit`은 별도 진단이며 성공 조건이 아니다.
- `evaluation_status`는 원시 실행 상태로 보존한다. 예를 들어 `invalid_response`와 `evaluation_validity=partial`, 최종 hit이 함께 존재할 수 있다.
- `scoring_complete`는 이제 전체 채점 유효 여부를 뜻한다. 검출 실행 완료와 묶지 않는다. 구버전 집계와 혼합하지 않는다.

검출 실행 근거는 요청된 측정·모듈의 상태로 기록한다. 기존 `execution_complete=false`만 있고 후보·상태 근거도 없으면 실패로 추정하지 않고 `unknown`이다.
입력/설정 실패 때문에 검출 산출물 자체가 없는 영상도 batch 구성자가 원래 계획의 행과 실패 상태를 남겨야 한다. 재집계기는 누락된 영상을 임의로 만들어 분모에 추가하지 않는다.

## 일부 유효의 보수적인 경계

현재 부분 보존은 **모든 R 독립 분석과 기본 R×C 비교의 검증이 완료된 뒤**, 일부 불일치 근거 검토 또는 재비교가 실패한 경우에만 적용한다.

1. 공통 분석/비교의 입력·요청 해시·원문 인용·ID·필드를 기존 검증기로 다시 확인한다.
2. 완료 단계의 순서와 내용, 마지막 실패 단계의 입력/해시를 검증한다. 성공 응답 일부를 임의로 잘라내 실패 기록으로 바꾸지 않는다.
3. 실패한 검토·재비교 및 이후 미실행 검토에 의존하는 쌍은 `evaluation_validity=unavailable`로 표시하고 판정에 사용하지 않는다.
4. 그와 무관한 유효 쌍은 보존한다. 재검토 응답만으로 최초 음성 판정을 양성으로 승격하지 않는다.
5. 공통 분석이나 기본 비교 자체가 무효이면 전체 비교는 무효다. 원시 JSON에서 좋아 보이는 쌍을 임의로 건지거나 원문 근거를 보정하지 않는다.

`valid_pair_count`, `unavailable_pair_count`, `evaluation_issues` 및 쌍별 `validation_reason`을 남긴다.
유효한 부분 결과라도 대응이 없으면 no_hit으로 확정하지 않는다. 누락/순서 변경/해시 불일치/공통 근거 변조는 오류로 거절한다.

## 출력과 재집계

영상별 JSON·CSV·HTML은 세 상태를 별도로 노출한다. summary에는 각 상태의 분포와
`hits_with_incomplete_detection`, `hits_with_partial_evaluation`을 기록한다.
과거 결과는 보존하고 새 폴더로 재집계한다. 의미 평가 프롬프트·스키마·요청 해시는 그대로라 유효한 기존 v6 캐시를 재사용할 수 있다.
기존 집계 폴더에 새 집계 버전으로 resume하지 않는다. 새 실행/집계 폴더를 사용한다.

```bash
.venv/bin/python -m review_anomaly_v4.event_reaggregate \
  --source work/parallel_pilot12_20261112 \
  --output work/parallel_pilot12_aggregation2_20261112
```

입력은 `rows.json`, `evaluations/<asset_id>.json`, 선택적 기존 `scorecard.json`이다.
행에 `report_path`가 있으면 미디어 해시·후보 내용/순서·검출 완료 플래그를 원본 report와 대조한다.
캐시가 없으면 미실행/pending으로 남기고 원격 호출을 하지 않는다. 캐시가 낡거나 다른 영상이면 거절한다.
`aggregation_manifest.json`에는 읽은 원본 파일 해시와 `remote_calls=0`을 기록한다.
